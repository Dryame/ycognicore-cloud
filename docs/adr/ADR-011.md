# ADR-011 : Job de maintenance partition via superuser

## Statut
Accepté — 30/09/2026

## Contexte
Le job automatique de création de partitions mensuelles doit créer des
tables partitionnées (audit_log, login_attempts) sur chaque base tenant.

Problème : le rôle applicatif ycc_tenant_app n'est pas propriétaire des
tables parentes (il a seulement SELECT, INSERT). Il ne peut donc pas
exécuter CREATE TABLE PARTITION OF.

Tentatives :
- GRANT CREATE ON table : erreur (CREATE n'existe pas au niveau table)
- ALTER ROLE SUPERUSER : trop large (violerait le moindre privilège)

## Décision
Le job de maintenance utilise le superuser postgres pour se connecter aux
bases tenant.

Concrètement : dans tenant_databases, db_user = 'postgres'.

## Justification
1. La création de partitions est une opération DDL d'administration
   légitime, pas une opération métier.
2. Le job est planifié, contrôlé, tracé (partition_maintenance_log).
3. Alternative (changer le propriétaire des tables) impacterait Flyway
   et l'isolation.
4. Compromis acceptable en Phase 1 (peu de tenants, environnement contrôlé).

## Conséquences

### Positives
- Job opérationnel (12 partitions créées sur 2 tenants, 0 erreur)
- Aucune modification des migrations Flyway
- Traçabilité complète dans partition_maintenance_log

### Négatives
- Utilisation d'un compte à privilèges élevés pour un job automatique
- À restreindre en production

## Action future (Phase 3)
Créer un rôle dédié ycc_partition_admin avec les privilèges minimaux
nécessaires (CREATE sur le schéma public des bases tenant).
