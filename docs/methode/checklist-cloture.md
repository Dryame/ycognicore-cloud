# Modèle de checklist de clôture

**Référence** : planning prévisionnel v1.1, annexe C
**Usage** : à remplir pour chaque phase avant sa clôture
**Principe** : une phase n'est terminée que si toutes les cases sont cochées

---

## 1. Critère de sortie de la phase

- [ ] Le critère de sortie défini par le planning est atteint
- [ ] La preuve du critère est fournie (test, rapport, démonstration)

## 2. Vérifications par famille

### 2.1 Le fonctionnement est vérifié par des tests

- [ ] Tests automatisés réussis (résultat : ____ / ____)
- [ ] Scénario nominal exécuté
- [ ] Cas limites testés

### 2.2 La sécurité est vérifiée

- [ ] Tests d'accès (RBAC, isolation entre entreprises)
- [ ] Absence de secret dans le dépôt
- [ ] Analyse de sécurité documentée

### 2.3 Les répercussions sur les autres modules sont contrôlées

- [ ] Tests de non-régression exécutés
- [ ] Vérification globale réussie
- [ ] Aucun test préexistant cassé

### 2.4 La documentation est à jour

- [ ] Fiche d'analyse rédigée
- [ ] MCD ou API à jour
- [ ] ADR rédigés si nécessaire
- [ ] README mis à jour si nécessaire
- [ ] BACKLOG mis à jour

### 2.5 Une démonstration a été faite à l'encadreur

- [ ] Démonstration réalisée
- [ ] Compte rendu de la démonstration rédigé

### 2.6 Le rapport journalier est rédigé

- [ ] Rapport journalier rédigé
- [ ] Preuves cohérentes (captures, sorties console)

---

## 3. Contrôles complémentaires du projet

- [ ] Messages d'erreur clairs pour l'utilisateur
- [ ] Détail technique uniquement dans les journaux
- [ ] BACKLOG mis à jour
- [ ] Matrice de traçabilité mise à jour
- [ ] Tag Git posé
